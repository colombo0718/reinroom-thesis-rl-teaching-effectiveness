> 檢核分七層，由抽象到具體：

### 一般學術八股結構（元智未強制，但學術社群期待）

#### 第一章 緒論必備元素

- [ ] **研究背景**：說明領域整體狀況與問題脈絡
- [ ] **研究動機**：為什麼要做這個研究
- [ ] **研究目的**：本研究要達成什麼
- [ ] **研究問題（RQ）**：條列式可回答的具體問題
- [ ] **研究範圍與限制**：明確界定本研究不處理什麼
- [ ] **名詞釋義**（Operational Definitions）：關鍵術語定義
- [ ] **論文架構**：簡介各章內容

#### 第二章 文獻探討必備元素

- [ ] **理論基礎**：本研究依據的核心理論
- [ ] **相關研究回顧**：分主題（review by topic）非分作者（review by author）
- [ ] **文獻間的對話**：呈現不同學者觀點的異同
- [ ] **研究缺口（Research Gap）**：明確指出文獻不足之處
- [ ] **本研究的定位**：說明本研究如何填補缺口
- [ ] 引用文獻數量合理（碩士論文一般 30–80 篇）
- [ ] 近期文獻比例平衡（近 5 年 / 近 10 年）

#### 第四章 研究方法必備元素

- [ ] **研究設計**：明確說明採用何種方法並說明理由
- [ ] **研究對象**：受試者描述
- [ ] **研究工具**：所用測驗、量表、觀察表
- [ ] **研究工具的信效度**：即便是「依研究目的設計」也需說明內容效度
- [ ] **資料蒐集程序**：時間表、實施步驟、控制變項
- [ ] **資料分析方法**：使用的統計方法、質性分析方法
- [ ] **研究倫理**：受試者同意、匿名處理、資料保管

#### 第五章 研究結果必備元素

- [ ] 結果呈現順序對應 RQ（RQ1 → RQ2 → RQ3）
- [ ] 描述統計與推論統計分開呈現
- [ ] 圖表先於文字解讀，文字解讀緊接圖表後
- [ ] 不在結果章直接做價值判斷（保留給結論章）

#### 第六章 結論與建議必備元素

- [ ] **研究發現摘要**（呼應 RQ 的回答）
- [ ] **研究貢獻**（理論 / 實務 / 方法學貢獻）
- [ ] **研究限制**（樣本、方法、推論範圍）
- [ ] **未來研究建議**
- [ ] **實務建議**（對教學現場、平台開發者的具體建議）

#### 學術寫作慣例

- [ ] **第三人稱客觀寫作**：以「本研究」「研究者」為主
- [ ] **避免絕對性陳述**：用「顯示」「傾向」「可能」而非「證明」「絕對」
- [ ] **引用文獻支撐論述**：理論性陳述後有文獻支撐
- [ ] **數據呈現符合學術慣例**：t(df)=值, p=值, d=效果量；M=平均, SD=標準差
- [ ] **圖表自我解釋**：圖表標題與註解能單獨被讀懂
- [ ] **章末小結與章首引言**：每章有開場提示與結尾統整

#### 關鍵術語的學術定義

- [ ] **強化學習（Reinforcement Learning）**：第一次出現有定義（Sutton & Barto, 2018）
- [ ] **Q-Learning / Q-Table**：第一次出現有定義
- [ ] **準實驗設計（quasi-experimental design）**：第一次出現有定義
- [ ] **Treatment Fidelity（教學介入忠實度）**：第一次出現有定義
- [ ] **NASA-TLX**：第一次出現有定義（Hart & Staveland, 1988）
- [ ] **SUS（System Usability Scale）**：第一次出現有定義（Brooke, 1996）
- [ ] **效果量、統計顯著性**：第一次出現有定義

#### 文獻引用品質

- [ ] **教育科技領域核心文獻**：Sutton & Barto（2018）、Sweller（1988）認知負荷、Mayer 多媒體學習理論
- [ ] **準實驗設計方法學**：Campbell & Stanley、Shadish et al.
- [ ] **Treatment Fidelity 文獻**
- [ ] **本研究類似主題的文獻**：UI-driven RL 教學、視覺化教學介面研究

#### 八股風險檢查

- [ ] **不像部落格文**：不用「大家好」「最近...」這類非學術口吻
- [ ] **不像產品手冊**：第三章扣回教育設計理念，不只是 RL Lab 功能介紹
- [ ] **不像企劃書**：第六章 6.4 推廣建議扣回研究發現，不要變成商業企劃
- [ ] **不像 AI 生成**：避免「綜合而言」「值得指出的是」過量套用
- [ ] **章節編號不跳號**：4.4.4 之後是 4.4.5
- [ ] **圖表編號不重複**：所有圖表編號全文唯一
- [ ] **參考文獻零未引用**：列在文末的每一篇文獻都要在文中至少出現一次

## 【可讀性層】語言流暢度與 AI 痕跡檢驗

> 一篇論文若每段都看得出 AI 風格，會大幅降低學術可信度。

### AI 痕跡

- [ ] 無對話式殘留：「你」「我」、「告訴我」「請你」等與讀者對話的口吻
- [ ] 無模板殘留：[待填]、[XX]、`{ }` 佔位符
- [ ] 無 emoji 過度使用（學術論文不應有 ✅ 🎯 等表情）
- [ ] 無重複的句式套用：避免每段都「綜合而言...本研究...」這類模板開頭
- [ ] 無「值得指出的是」「值得注意的是」過量使用

### 語言流暢度

- [ ] 中文流暢、無翻譯腔
- [ ] 句子長度有變化，不是每句都 50 字以上
- [ ] 段落之間有過渡語句，不是硬接
- [ ] 專業術語第一次出現時有英文對照（state、Q-table、Treatment Fidelity 等）
- [ ] 數字、英文與中文之間留半形空格（標楷體與 Times New Roman 之間視覺要乾淨）

### 命名一致性

- [ ] 平台名稱：論文內統一稱「RL Lab」（首次出現註明 Rein Room 為正式名稱）
- [ ] 第三章章名保留「Rein Room 平台設計」（正式章名可用全名）
- [ ] 無 RR / ReinRoom / 強化教室 在內文混用
- [ ] 兩組稱呼一致：實驗組 A、對照組 B
- [ ] 任務命名一致：T1 MAB / T2 Maze1D / T3 Maze2D / T4 Heli / T5 Fighter

## 檢核流程建議

1. **本人通讀**：研究者本人逐章閱讀，先處理「研究貢獻層」與「論證層」（這兩層 AI 難以判斷）
2. **Codex / Gemini 交叉比對**：跑「事實層」、「學術規範層」與「可讀性層」的自動檢核
3. **指導教授過目**：「研究貢獻層」與「學術規範層」最終由指導教授裁示
4. **重大修改後再跑一次**：每次論文有重大改動後（例如加新章節、改數據呈現），重新跑整份 checklist
5. **口試前最後一輪**：確認「格式層」全部過關
6. **回饋更新**：檢核發現的問題若反映 checklist 沒涵蓋的維度，把新問題類型補回 checklist
