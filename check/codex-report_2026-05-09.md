# 論文_組裝.docx 格式審查報告（元智格式規範 A）

檢驗日期：2026-05-09  
檢驗對象：`論文_組裝.docx`  
檢驗方式：直接檢查 DOCX OOXML 結構（`document.xml`、`styles.xml`、section/page setup、header/footer/field code）並對照 `元智格式規範/md`、官方範本 DOCX、`CLAUDE.md` 摘要。

初步結論：目前 `論文_組裝.docx` 不能視為符合元智格式 A 的完整論文稿。已符合的部分主要是頁邊距、中英文分字型、正文/章節的主要字級與正文 1.2x 行距；主要不符點包括：紙張仍是 Letter 而非 A4、完全沒有頁碼系統、缺少目錄/表目錄/圖目錄與多個前後置必要項目、正文沒有 2 字首行縮排、表格編號仍採章內編號且與圖號規則不一致。

## 1. 頁面邊距
- 項目名稱：頁面邊距（上下左右）
- 規範要求：`元智格式規範/md/R-G-A00-new.md:25` 明定上 `3.5cm`、左 `4cm`、右 `2cm`、下 `2cm`。
- docx 實際呈現：section 1 的 `w:pgMar` 為 top `1984`、bottom `1134`、left `2268`、right `1134` twips，換算約為上 `3.50cm`、下 `2.00cm`、左 `4.00cm`、右 `2.00cm`。
- 是否符合：✅

## 2. 字型（中英文分別）
- 項目名稱：字型
- 規範要求：`CLAUDE.md:53` 摘要為中文 `標楷體`、英文 `Times New Roman`；官方範本正文與摘要樣本也都以中文楷體搭配英文 Times New Roman 為主。
- docx 實際呈現：抽樣檢查章名、節名、正文、圖說、表格文字，`w:rFonts eastAsia=標楷體`，`ascii/hAnsi=Times New Roman`；英文片語如 `Artificial Intelligence`、`Reinforcement Learning`、`Q-Table` 皆落在英文 font 設定中。
- 是否符合：✅

## 3. 字級（章名 / 節名 / 小節 / 正文 / 圖說 / 表格）
- 項目名稱：字級
- 規範要求：`CLAUDE.md:54` 摘要為正文 `14pt`、章名 `20pt`、節名 `16pt`、小節 `14pt` 粗體。官方章節範例 `R-G-A13_章節範例.docx` 亦對應到章名 20pt、其餘層級約 14pt。
- docx 實際呈現：
- 章名：`20pt`（`w:sz=40`），例如 `第一章　緒論`。
- 節名：`16pt`（`w:sz=32`），例如 `第一節　研究背景與動機`。
- 第三級層次（如 `壹、強化學習的核心原理`）：`14pt` 粗體（`w:sz=28`）。
- 正文：`14pt`（`w:sz=28`）。
- 圖說：`12pt` 粗體置中（`w:sz=24`）。
- 表格內文：`12pt` 置中（`w:sz=24`）。
- 表說：多數是 `14pt` 粗體靠左，實際上是被當成一般粗體段落，而非獨立表說樣式。
- 是否符合：⚠️ 部分符合
- build_thesis.py 對應程式位置與建議修法：章名/節名/正文對得上 `build_thesis.py:186-223`；但圖說被硬寫成 `12pt` 於 `build_thesis.py:243-249`，表格內文被硬寫成 `12pt` 於 `build_thesis.py:264-285`。若後續要完全貼齊格式 A，建議把「圖說字級」與「表格字級」改成可設定常數，並先以官方樣本或系所要求再確認是否應與正文同級。

## 4. 行距（各區塊）
- 項目名稱：行距
- 規範要求：`CLAUDE.md:55` 摘要為正文 `1.2x`，摘要/誌謝/參考文獻 `1.5x`；`元智格式規範/md/R-G-A00-new.md:81` 亦明定正文中文為單行系統、章名下留雙倍行距。
- docx 實際呈現：
- 正文、章名、節名、圖說、表格內段落，幾乎全部都是 `w:line=288, lineRule=auto`，即 `1.2x`。
- 章名另有 before/after `28pt`，符合章名下額外留白的做法。
- 但本檔沒有中文摘要、英文摘要、誌謝、參考文獻等正式區塊，因此無從呈現也無從檢查 `1.5x` 區塊。
- 是否符合：⚠️ 部分符合
- build_thesis.py 對應程式位置與建議修法：`set_spacing()` 在 `build_thesis.py:162-173` 被全域固定為乘數式行距；`add_chapter_title/add_section/add_subsection/add_subhead/add_body/add_fig_caption/add_table` 在 `build_thesis.py:186-285` 全都套同一路線。若日後要做完整格式 A，應新增「摘要/誌謝/參考文獻」專用函式，將其行距改為 `1.5x`，而不是沿用正文設定。

## 5. 章節編號層次
- 項目名稱：章節編號層次
- 規範要求：`元智格式規範/md/R-G-A00-new.md:76-80` 與 `元智格式規範/md/R-G-A13_章節範例.md:1-25` 顯示格式 A 的傳統層次至少應維持 `第一章 → 第一節 → 壹 → 一/問卷調查法 → 1、...`；`CLAUDE.md:57` 摘要亦明示 `第一章 → 第一節 → 壹 → 一 → 1`。
- docx 實際呈現：
- 前三層大致有做到：`第一章`、`第一節`、`壹、`。
- 但更深層次混用 `（一）`、未編號粗體小標、甚至原始數字層級 `4.6.2.1 三層次的統計切法策略`。
- 亦出現像 `研究範圍`、`前測階段`、`本節小結` 這類無傳統編號的粗體小標，整體層次不夠一致。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：`convert_section_text()` 只把 `X.Y` 轉成 `第一節`（`build_thesis.py:51-56`），`convert_subsection_text()` 只把 `X.Y.Z` 轉成 `壹、`（`build_thesis.py:58-63`）。正則式 `RE_SUBSEC` / `RE_SEC` / `RE_CN_SUB`（`build_thesis.py:106-113`）與 `classify_bold_line()`（`build_thesis.py:314-329`）都沒有處理更深層的傳統編號，所以深層標題會落成原始數字或 generic subhead。建議未來新增完整的層級正規化規則，而不是只轉兩層。

## 6. 圖表編號方式（是否連續、樣式是否符合）
- 項目名稱：圖表編號
- 規範要求：`元智格式規範/md/R-G-A00-new.md:73` 明定「文內表圖，各依應用順序，不分章節連續編號」。
- docx 實際呈現：
- 圖號為 `圖 1` 到 `圖 21`，全篇連續、無缺號。
- 表號則是 `表 3-1`、`表 3-2`、...、`表 6-3`，仍沿用章內編號。
- 另外還出現一個重複的 `表 3-4`：先有敘述性粗體句，再有真正表說 `表 3-4　RL Lab 官方環境比較`，樣式上容易讓人誤判為重複表說。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：圖號之所以合規，是因為有 `FigureRegistry` 與 `build_fig_registry()` 先全文登記再轉號（`build_thesis.py:123-145`, `443-452`）；表格完全沒有對應的 `TableRegistry`，`add_table()` 只負責插表本體（`build_thesis.py:264-285`），因此表說仍保留原始章內編號。建議未來為表格建立與圖相同的全文連號機制，並把表說文字做一次統一清洗。

## 7. 圖說、表說位置與字級
- 項目名稱：圖說 / 表說位置與字級
- 規範要求：`元智格式規範/md/R-G-A00-new.md:107-108` 明定「表號及表名列於表上方，圖號及圖名置於圖下方」。
- docx 實際呈現：
- 圖說：所有正式圖說都在含 drawing 的圖片段落之後，位置正確；字級為 `12pt` 粗體置中。
- 表說：大多數表說都在 top-level table 之前，位置正確；字級約 `14pt` 粗體靠左。
- 但圖說與表說樣式不一致，且同一份文件內的 caption 標點也不一致，例如 `圖 1　...`、`圖 16：...`、`表 3-1　...`、`表 4-1 ...` 同時存在。
- 是否符合：⚠️ 部分符合
- build_thesis.py 對應程式位置與建議修法：圖說位置由 `figcaption/md_image` 事件先插圖、再呼叫 `add_fig_caption()` 決定（`build_thesis.py:506-524`），字級固定在 `build_thesis.py:243-249`。表說沒有專用函式，實際上是靠 markdown 解析後作為一般粗體段落輸出，再接 `add_table()`（`build_thesis.py:314-329`, `395-413`, `527-528`），所以無法保證 caption 樣式一致。建議未來建立獨立 `add_table_caption()` 與 caption normalization。

## 8. 段落首行縮排（中文段落 2 字元）
- 項目名稱：首行縮排
- 規範要求：`CLAUDE.md` 摘要明示中文段落首行縮排 `2 字元`；官方章節範例的正文段落也可見首行縮排痕跡。
- docx 實際呈現：正文段落普遍沒有 `w:ind firstLine` 或 `firstLineChars`，等於首行不縮排；包括第一章內多數正文都是齊左開始。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：`add_body()` 與 `add_list_item()` 只設定對齊與行距，沒有設定首行縮排（`build_thesis.py:218-232`）；`set_spacing()` 也只管 spacing，不管 indent（`build_thesis.py:162-173`）。建議未來新增 `set_indent()` 或直接在正文 paragraph 上設定 `first_line_indent` / `firstLineChars=200`。

## 9. 頁碼位置與格式
- 項目名稱：頁碼
- 規範要求：`元智格式規範/md/R-G-A00-new.md:25` 要求頁次置於版面底端 1 公分處中央；`R-G-A00-new.md:67-68` 另要求前置部分用小寫羅馬數字、本文與附錄用阿拉伯數字。
- docx 實際呈現：
- 文件內沒有任何 `header*.xml` / `footer*.xml`。
- 沒有 `PAGE` field，也沒有 `w:pgNumType`。
- 全檔只有 1 個 section，章與章之間只是 page break，不是 section break。
- 因此目前既沒有頁碼，也不具備切換「羅馬數字前置頁 / 阿拉伯數字正文頁」的結構。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：`build()` 只建立空白 `Document()` 並設 margins（`build_thesis.py:454-462`），`add_page_break()` 只插入換頁符號（`build_thesis.py:259-262`），章切換時也只是呼叫 page break（`build_thesis.py:486-489`）。整個檔案沒有任何 footer、page field、section break、頁碼格式切換邏輯。建議未來若要修正，必須改成至少「前置 section / 正文 section」兩段式結構。

## 10. 目錄、圖目錄、表目錄是否存在
- 項目名稱：目錄 / 表目錄 / 圖目錄
- 規範要求：`元智格式規範/md/R-G-A00-new.md:9-13,72-73` 與 `R-G-A9_目錄中.md`, `R-G-A10_表目錄中.md`, `R-G-A11_圖目錄中.md` 都把目錄、表目錄、圖目錄列為正式項目。
- docx 實際呈現：文件直接從 `第一章　緒論` 開始；找不到 `目錄`、`表目錄`、`圖目錄` 專屬段落，也沒有任何 TOC field code。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：`CHAPTERS` 常數只列出六章本文 md（`build_thesis.py:65-103`），`build()` 事件流程也只會輸出章節、內文、圖、表（`build_thesis.py:485-530`）。完全沒有前置項目與目錄生成邏輯。建議未來把前置頁加入組裝流程，並加上 TOC / LOT / LOF 欄位或至少預留標題頁。

## 11. 其他元智格式 A 明文規定細節
- 項目名稱：其他明文規定
- 規範要求：
- `元智格式規範/md/R-G-A00-new.md:3-17` 規定完整論文次序應包含封面、書名頁、審定書、中英摘要、誌謝、目錄、表目錄、圖目錄、符號說明、本文、參考文獻、附錄、封底。
- `R-G-A00-new.md:24` 明定紙張為 `A4 (210mm × 297mm)`。
- docx 實際呈現：
- 文件只包含本文六章，沒有封面、書名頁、審定書、中英摘要、誌謝、表目錄、圖目錄、符號說明、參考文獻、附錄等完整論文要件。
- 紙張尺寸仍是 Word 預設 Letter：`21.59cm × 27.94cm`，不是 A4 `21.0cm × 29.7cm`。
- footer distance 仍是預設 `720` twips（約 `1.27cm`），即使未來加頁碼，也還不是規範寫的「底端 1 公分處」。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：根本原因是 `build()` 直接從空白 `Document()` 開始（`build_thesis.py:454-455`），而不是以官方格式範本為底，也沒有設定 `page_width/page_height`。前置/後置缺項則來自 `CHAPTERS` 只列本文 md（`build_thesis.py:65-103`）。若未來要修，優先順序應是：先改成 A4 與 section 架構，再補前置/後置頁，最後才調 caption/表格細節。

## 建議優先修正順序（僅供人類後續決策）
- 第 1 優先：紙張改為 A4、補 section/page numbering 結構，否則整份文件從版面層級就不是格式 A。
- 第 2 優先：補齊完整論文前置與後置項目（中英摘要、誌謝、目錄、表目錄、圖目錄、參考文獻、附錄等）。
- 第 3 優先：補正文 2 字首行縮排，統一深層章節層次。
- 第 4 優先：統一圖說/表說樣式，讓表號也改為全文連號。
