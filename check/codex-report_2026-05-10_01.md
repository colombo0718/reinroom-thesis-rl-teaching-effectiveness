# 論文_組裝.docx 元智格式 A 檢驗報告

檢驗日期：2026-05-10  
檢驗對象：`論文_組裝.docx`  
來源程式：`build_thesis.py`  

檢驗方法說明：
- 本次以 DOCX 的 OOXML 結構直接檢查 `document.xml`、`styles.xml`、section/page setup、footer/field code，並對照 `元智格式規範/md/`、官方範本與 `CLAUDE.md` 摘要。
- 本機環境未安裝 `LibreOffice/soffice`，因此未進行 PNG 視覺渲染；與頁碼、目錄欄位相關的判斷以 Word field 與 section 結構為準。

整體結論：
- 這一版比 2026-05-09 明顯進步，已補上 A4、頁邊距、首行縮排、前置頁、TOC field、PAGE field、表格全文連號機制等。
- 但 `論文_組裝.docx` 仍未完全符合元智格式 A。主要問題集中在：前置頁模板仍是 placeholder、頁碼 section 格式前後顛倒且未隱藏書名頁/審定書頁碼、目錄/圖目錄/表目錄尚未更新且順序錯、圖說重複、表號碰撞、深層章節層次仍混用 `（一）` / 無編號小標。

- docx 實際呈現：section page margin 為 top `1984`、bottom `1134`、left `2268`、right `1134` twips，約為上 `3.50cm`、下 `2.00cm`、左 `4.00cm`、右 `2.00cm`。
- 是否符合：✅
- build_thesis.py 對應程式位置與建議修法：目前由 `build_thesis.py:640-648` 設定，這部分與規範一致，暫無需修法。

## 3. 字級（章名 / 節名 / 小節 / 正文 / 圖說 / 表格）
- 項目名稱：字級
- 規範要求：`CLAUDE.md:54` 摘要為正文 `14pt`、章名 `20pt`、節名 `16pt`、小節 `14pt` 粗體。
- docx 實際呈現：
- 章名：`20pt`（`w:sz=40`），例如 `第一章　緒論`。
- 節名：`16pt`（`w:sz=32`），例如 `第一節　研究背景與動機`。
- 第三級層次：`14pt` 粗體（`w:sz=28`），例如 `壹、強化學習的核心原理`。
- 正文：`14pt`（`w:sz=28`）。
- 圖說：`12pt` 粗體置中（`w:sz=24`）。
- 表說：`12pt` 粗體置中（`w:sz=24`）。
- 表格內文：`12pt`（`w:sz=24`）。
- 是否符合：⚠️ 部分符合
- build_thesis.py 對應程式位置與建議修法：章/節/小節/正文已對齊 `build_thesis.py:306-355`；但圖說、表說、表格內文都被硬寫成 `12pt`（`build_thesis.py:393-407`, `422-444`）。官方文字版未明列 caption 字級，因此保守記為部分符合；若後續要完全對齊官方範本，建議以範本頁為基準，把 caption/table 字級抽成常數設定。

## 4. 行距（各區塊）
- 項目名稱：行距
- 規範要求：`CLAUDE.md:55` 與 `元智格式規範/md/R-G-A00-new.md:81` 指正文 `1.2x`，摘要/誌謝/參考文獻 `1.5x`。
- docx 實際呈現：
- 正文、章名、節名、圖說、表說、表格段落：`1.2x`（`w:line=288`）。
- 摘要、英文摘要、誌謝、參考文獻正文：`1.5x`（`w:line=360`）。
- 但參考文獻中的清單條目仍是 `1.2x`，例如「待補書目」下的 `•` 條列。
- 是否符合：⚠️ 部分符合
- build_thesis.py 對應程式位置與建議修法：`add_body_15x()` 已正確處理摘要/誌謝/參考文獻正文（`build_thesis.py:349-355`），但 `add_list_item()` 永遠使用 `1.2x`（`build_thesis.py:375-382`），不會隨參考文獻章節切換。若未來要完全合規，建議讓 list item 也能依區塊套用 `1.5x`。

## 5. 章節編號層次
- 項目名稱：章節編號層次
- 規範要求：`CLAUDE.md:57` 與 `元智格式規範/md/R-G-A00-new.md:76-80` 指出傳統層次應為 `第一章 → 第一節 → 壹 → 一 → 1`。
- docx 實際呈現：
- 前三層已有改善，確實出現 `第一章`、`第一節`、`壹、`。
- 但深層層次仍混用 `（一）...`、`本節小結`、`研究範圍` 等非傳統格式。
- 在第六章可見 `（一）控制單頁資訊密度...` 直接被做成 `Heading 2 / 16pt`，等同與「第一節」同層，階層不正確。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：
- `convert_section_text()` 只把 `X.Y` 轉成 `第一節`（`build_thesis.py:55-60`）。
- `convert_subsection_text()` 只把 `X.Y.Z` 轉成 `壹、`（`build_thesis.py:62-67`）。
- `parse_md()` 對任何不符合 `X.Y` / `X.Y.Z` / `一、` 的 markdown heading，直接落到 `section`（`build_thesis.py:523-538`），因此 `## （一）...` 會被升成 `Heading 2`。
- 建議：新增 `（一）`、`1、` 等層級辨識規則，或在 builder 端強制把 deeper heading 正規化成格式 A 的傳統序列。

## 6. 圖表編號方式（是否連續、編號樣式是否符合）
- 項目名稱：圖表編號
- 規範要求：`元智格式規範/md/R-G-A00-new.md:73` 明定「文內表圖，各依應用順序，不分章節連續編號」。
- docx 實際呈現：
- 圖號表面上是 `圖 1` 到 `圖 21`，但 `圖 1`、`圖 3` 到 `圖 15` 都各出現兩次，而且是「圖片 + 圖說」成對重複輸出。
- 表號表面上已改為全文編號 `表 1` 到 `表 25`，但仍出現碰撞：`表 16`、`表 21`、`表 22` 各有兩張不同的表使用同一號碼。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：
- 圖重複的主因是 `parse_md()` 現在把 `![圖 ...](...)` 與 `**圖 ...**` 分別當成 `md_image` 與 `figcaption` 兩個事件處理，已沒有舊版的去重邏輯（`build_thesis.py:508-512`, `541-545`, `715-733`）。目前 `md/3.1`、`3.2`、`3.3`、`3.4` 仍大量保留雙寫法，因此會輸出兩次。
- 表碰撞的主因是 `TableRegistry` 以原始 `表 X-Y` 作為字典 key（`build_thesis.py:158-179`）。當不同檔案重用了相同原始表號，例如 `md/5.2` 與 `md/5.3` 都有 `表 5-6`，`md/5.3` 與 `md/5.4` 都有 `表 5-11`、`表 5-12`，builder 會把不同表壓成同一個全文號。
- 建議：圖要恢復 `md_image + figcaption` 去重；表則不應只用原始表號當唯一 key，至少要把「出現順序」或「事件序號」納入 mapping。

## 7. 圖說、表說位置與字級
- 項目名稱：圖說 / 表說位置與字級
- 規範要求：`元智格式規範/md/R-G-A00-new.md:107-108` 明定「表號及表名列於表上方，圖號及圖名置於圖下方」。
- docx 實際呈現：
- 真正的圖說大多在圖片下方，表說大多在表格上方，位置大致正確。
- 但多數圖片實際是「圖片 → 圖說 → 圖片 → 圖說」重複一組，例如圖 1、圖 3、圖 4、圖 5。
- 表說字級為 `12pt` 粗體置中；圖說亦為 `12pt` 粗體置中。
- caption 標點未完全統一，仍可見 `圖 16：...`、`圖 17：...` 這類全形冒號樣式，而不是統一成 `圖 16　...`。
- 是否符合：⚠️ 部分符合
- build_thesis.py 對應程式位置與建議修法：
- 圖說 / 表說位置是由 `add_fig_caption()` 與 `add_table_caption()` 控制（`build_thesis.py:393-407`），其位置本身沒問題，問題在於事件流重複。
- 標點統一函式 `normalize_caption_punct()` 只處理空白與 ASCII `:`，沒有處理全形 `：`，所以 `圖 16：...` 不會被正規化（`build_thesis.py:182-190`）。
- 建議：先修正圖事件重複，再把 caption punctuation normalization 擴充到全形冒號。

## 8. 段落首行縮排（中文段落 2 字元）
- 項目名稱：首行縮排
- 規範要求：`CLAUDE.md` 摘要要求中文段落首行縮排 `2 字元`。
- docx 實際呈現：

- 標題與表說/圖說不縮排，符合常見排版預期。
- 是否符合：✅
- build_thesis.py 對應程式位置與建議修法：`set_first_line_indent_chars()` 與 `add_body()` / `add_body_15x()` 已正確套用（`build_thesis.py:221-232`, `341-355`），暫無需修法。

## 9. 頁碼位置與格式
- 項目名稱：頁碼位置與格式
- 規範要求：
- `元智格式規範/md/R-G-A00-new.md:25`：頁碼應在版面底端 `1cm` 處中央。
- `R-G-A00-new.md:67-68`：前置部分應為小寫羅馬數字 `i, ii, iii...`，正文起改阿拉伯數字 `1, 2, 3...`。
- 書名頁、審定書雖要計入頁次，但不應印出頁碼。
- docx 實際呈現：
- footer distance 已設為 `567` twips，約 `1.00cm`，且有中央 `PAGE` field。
- 但 section 結構前後顛倒：第 40 個 top-level 段落上的 `sectPr` 設成 `decimal start=1`，`body` 末端的最終 `sectPr` 卻是 `upperRoman start=1`。依 OOXML section 套用順序判斷，前置頁與正文的頁碼格式很可能反了。
- builder 使用的是 `upperRoman`，規範要的是小寫羅馬數字。
- 結構中沒有 `titlePg`，也沒有任何「首頁不顯示頁碼」控制；書名頁/審定書頁碼很可能會直接印出來。
- 是否符合：❌
- build_thesis.py 對應程式位置與建議修法：
- `add_page_number_field()` 與 `set_section_page_format()` 本身沒問題（`build_thesis.py:250-265`）。
- 問題在 `set_section_page_format(doc.sections[0], fmt='upperRoman', start=1)` 後再手動插入 `add_section_break(... decimal ...)`（`build_thesis.py:662-667`）。目前這個 sectPr 掛載位置讓前後 section 格式倒置。
- 另外 `build_thesis.py:651-655` 只建立一份共用 footer，沒有對書名頁/審定書做頁碼抑制。
- 建議：重做 section 切分流程，確認「前置 section = lowerRoman」「正文 section = decimal」，並對不應顯示頁碼的前置頁使用獨立 section 或 first-page/no-footer 設定。
