# 元智大學論文格式 A 檢驗報告

- 檢驗日期：2026-05-10
- 檢驗對象：`論文_組裝.docx`
- 追因程式：`build_thesis.py`
- 規範依據：
- `CLAUDE.md`
- `元智格式規範/md/R-G-A00-new.md`
- `元智格式規範/md/R-G-A9_目錄中.md`
- `元智格式規範/md/R-G-A10_表目錄中.md`
- `元智格式規範/md/R-G-A11_圖目錄中.md`
- `元智格式規範/md/R-G-A12_符號說明.md`
- `元智格式規範/md/R-G-A13_章節範例.md`
- 官方範本抽樣比對：`R-G-A5_中文摘要.docx`、`R-G-A8_誌謝中.docx`、`R-G-A12_符號說明.docx`、`R-G-A14_參考文獻中.docx`
- 檢驗方式：直接解析 `docx` 的 OOXML 結構、抽樣比對官方範本、回查 `build_thesis.py` 對應邏輯

## 1. 頁面尺寸與邊距

- 項目名稱：頁面尺寸與邊距
- 規範要求：A4；上 3.5cm、左 4cm、右 2cm、下 2cm；頁碼置於版面底端 1cm 中央。來源：`R-G-A00-new.md:24-25`
- docx 實際呈現：頁面大小 21.0cm × 29.7cm；上 3.5cm、左 4.0cm、右 2.0cm、下 2.0cm；footer 距底端 1.0cm。
- 是否符合：✅

## 2. 字型

- 項目名稱：中英文字型
- 規範要求：中文 `標楷體`、英文 `Times New Roman`。來源：`CLAUDE.md`
- docx 實際呈現：正文、章名、節名、圖說、表說、表格儲存格抽樣皆為中文 `標楷體`、英文 `Times New Roman`。
- 是否符合：✅

## 3. 字級

- 項目名稱：章名 / 節名 / 小節 / 正文 / 圖說 / 表格字級
- 規範要求：正文 14pt、章名 20pt、節名 16pt、小節 14pt 粗體；圖說與表說依官方範本為 12pt。來源：`CLAUDE.md`，官方範本抽樣
- docx 實際呈現：章名 20pt、節名 16pt、子層標題 14pt 粗體、正文 14pt、圖說 12pt 粗體、表說 12pt 粗體、表格內容抽樣為 12pt。
- 是否符合：✅

## 4. 行距

- 項目名稱：各區塊行距
- 規範要求：正文 1.2 倍；摘要 / 誌謝 / 參考文獻 1.5 倍。來源：`CLAUDE.md`、`R-G-A00-new.md:81`
- docx 實際呈現：正文與章節標題段落為 1.2 倍；中文摘要、英文摘要、誌謝、參考文獻條目抽樣為 1.5 倍。
- 是否符合：✅

## 5. 章節編號層次

- 項目名稱：章節編號層次
- 規範要求：`第一章 → 第一節 → 壹、 → 一、 → 1`。來源：`R-G-A00-new.md:76`、`R-G-A13_章節範例.md`
- docx 實際呈現：`第一章`、`第一節`、`壹、` 層次已存在；但 `一、` 層次未穩定出現。文件中 `Heading4` 數量為 0，且 `4.6.2.1`、`4.6.2.2`、`4.6.2.3` 這類更深層標題被當成 `Heading3`，導致層次扁平化。
- 是否符合：⚠️ 部分符合
- 不符對應程式位置：`build_thesis.py:108-123`、`build_thesis.py:333-363`、`build_thesis.py:552-568`
- 建議修法：`RE_SUBSEC = r'^\\d+\\.\\d+\\.\\d+'` 目前會把 `4.6.2.1` 也吃成三級標題；應分開辨識 `X.X.X`、`X.X.X.X`、`一、`、`（一）` 等層級，並讓第四層有獨立渲染函式與樣式，而不是全部落到 `Heading3` 或一般粗體段落。

## 6. 圖表編號方式

- 項目名稱：圖表編號連續性與樣式一致性
- 規範要求：圖、表應各自全論文連續編號，且標示樣式一致。來源：`R-G-A00-new.md:73`、官方圖表目錄範本
- docx 實際呈現：圖說共 21 筆，編號為 `圖 1` 到 `圖 21`，無重號；表面上以 `表 N` 開頭的段落共 29 筆，其中真正表說為連續的 `表 1` 到 `表 28`，但正文另有一段 `表 4　對五個官方環境從教學角度做橫向比較...`，造成讀者視覺上出現第二個 `表 4`。此外，圖 1 到圖 15 使用 `圖 N　標題`，圖 16 到圖 21 改成 `圖 N：標題`，分隔符不一致。
- 是否符合：⚠️ 部分符合
- 不符對應程式位置：`build_thesis.py:206-215`、`build_thesis.py:510-590`、`build_thesis.py:774-782`
- 建議修法：
- `normalize_caption_punct()` 目前只會正規化空格與半形冒號，沒有處理全形冒號 `：`，所以後段圖說樣式未統一。
- `parse_md()` 對正文中以 `表 N` 起首的敘述句沒有防呆，導致這種段落進入 `body` 後仍保留 `表 4` 前綴；應在 markdown 規範或 parser 中攔截這類偽表說。

## 7. 圖說、表說位置與字級

- 項目名稱：圖說 / 表說位置與字級
- 規範要求：表說在表上方，圖說在圖下方；字級依官方範本為 12pt。來源：`R-G-A00-new.md:108`、官方圖表範本
- docx 實際呈現：實際圖說均位於圖片下方，表說均位於表格上方，且抽樣為置中 12pt 粗體；但 `表 4` 前仍多出一段看起來像表說的正文，會讓該處表說視覺上重複。
- 是否符合：⚠️ 部分符合
- 不符對應程式位置：`build_thesis.py:510-590`、`build_thesis.py:774-790`
- 建議修法：保留現在 `add_table_caption()` / `add_fig_caption()` 的位置邏輯，但應補一層前處理，把正文中「看起來像 caption 但其實是敘述句」的 `表 N ...` 清掉或改寫，避免與真正 caption 並列。

## 8. 段落首行縮排

- 項目名稱：中文段落首行縮排
- 規範要求：中文正文段落首行縮排 2 字元。來源：`CLAUDE.md`
- docx 實際呈現：正文、摘要、誌謝、參考文獻條目抽樣皆為 `firstLineChars=200`，可對應為 2 字元首行縮排；圖說、表說與章節標題未縮排。
- 是否符合：✅

## 9. 頁碼位置與格式

- 項目名稱：頁碼位置、頁碼格式、前置頁是否隱藏頁碼
- 規範要求：頁碼置中於底端 1cm；中文摘要至圖表目錄等以前置頁小寫羅馬數字 `i, ii, iii...` 連續編頁；書名頁、審定書雖不印頁碼，但仍應納入同一套頁次。來源：`R-G-A00-new.md:25`、`R-G-A00-new.md:67`、`R-G-A9_目錄中.md:2-6`
- docx 實際呈現：footer 的確有置中 `PAGE` field，且 footer 距底端 1cm；但 OOXML 結構中，正文前的 inline `sectPr` 被寫成 `decimal start=1`，最末 section 又沒有明確 `pgNumType`，文件中也沒有 `w:titlePg`。換句話說，檔內結構沒有確立「前置頁小寫羅馬、正文阿拉伯數字」這件事，也沒有看到「書名頁 / 審定書不印頁碼」所需的不同首頁控制。
- 是否符合：❌
- 不符對應程式位置：`build_thesis.py:274-289`、`build_thesis.py:291-310`、`build_thesis.py:690-707`
- 建議修法：
- `build()` 內對 section 的假設與 OOXML 實際落點不一致；目前 `add_section_break(... lowerRoman ...)` 與 `set_section_page_format(doc.sections[0], decimal ...)` 最終寫出的 section 不是規劃中的那一個。
- 需要明確把前置 section 設為 `lowerRoman`，再把正文 section 設為 `decimal start=1`。
- 書名頁與審定書若要「計頁但不顯示」，還需要不同首頁或獨立 section/footer 控制；目前 `add_page_number_field()` 對所有 section 一律放同一個 `PAGE` field，無法達成。

## 10. 目錄、表目錄、圖目錄、符號說明

- 項目名稱：目錄 / 表目錄 / 圖目錄 / 符號說明
- 規範要求：應依序具備 `目錄 → 表目錄 → 圖目錄 → 符號說明`。來源：`R-G-A00-new.md:72-74`、`R-G-A9_目錄中.md`
- docx 實際呈現：`目錄`、`表目錄`、`圖目錄` 三頁已存在，順序也正確；TOC field 也有插入。但目前檔內仍只有空白 field 與提示文字 `（請於 Word 中按 F9 更新目錄）`，尚未存出實際目錄內容。`符號說明` 頁完全缺失。
- 是否符合：⚠️ 部分符合
- 不符對應程式位置：`build_thesis.py:381-397`、`build_thesis.py:669-674`
- 建議修法：
- `add_toc_field()` 不應把提示文字保留在最終審查版；至少要提供 final mode，不再輸出這三行提示。
- `add_front_matter()` 需補上 `符號說明` 頁。若系所確認本論文可免附，才可在規格上另行註記為例外。

## 11. 前置頁是否符合官方附件版型

- 項目名稱：封面 / 書名頁 / 審定書 / 摘要 / 誌謝之前置頁版型
- 規範要求：前置各頁應依附件一、二、三、五、六、八之官方版型排版。來源：`R-G-A00-new.md:19-23`，官方範本 `R-G-A1_封面.docx`、`R-G-A2_書名頁.docx`、`R-G-A3_審定書.docx`、`R-G-A5_中文摘要.docx`、`R-G-A6_英文摘要.docx`、`R-G-A8_誌謝中.docx`
- docx 實際呈現：
- 封面、書名頁、審定書仍是三個 placeholder 頁：`【封面：請依元智規範手動製作或由系所提供範本】`、`【書名頁...】`、`【論文口試委員審定書...】`
- 中文摘要頁沒有官方範本中的題名 / 學生 / 指導教授 / 系所資訊，也沒有 `摘        要` 標題，直接從摘要本文開始。
- 英文摘要只有 `Abstract` 標題與本文，沒有官方摘要頁版型。
- 誌謝頁沒有 `誌        謝` 標題，仍保留 `【作者姓名】　謹誌` placeholder。
- 是否符合：❌
- 不符對應程式位置：`build_thesis.py:633-667`
- 建議修法：不要再用 generic `add_chapter_title()` 湊前置頁。應分別做 `add_cover_page()`、`add_title_page()`、`add_approval_page()`、`add_cn_abstract_page()`、`add_en_abstract_page()`、`add_ack_page()`，直接對齊各官方附件的欄位與版式。

## 12. 參考文獻版式補充觀察

- 項目名稱：參考文獻條目縮排
- 規範要求：文字版規範明講 1.5 倍行距；官方 `R-G-A14_參考文獻中.docx` 範本中的條目未見與正文相同的 2 字首行縮排。
- docx 實際呈現：參考文獻條目已是 1.5 倍行距，但仍套用 `firstLineChars=200`，也就是與正文相同的 2 字首行縮排。
- 是否符合：⚠️ 部分符合
- 不符對應程式位置：`build_thesis.py:373-379`、`build_thesis.py:789-790`
- 建議修法：若要更貼近附件十四，參考文獻應改用獨立的 paragraph builder，不要沿用 `add_body_15x()` 的正文縮排設定。

## 總結

- 已明確符合：A4、邊距、字型、章/節/正文基本字級、正文 1.2 倍行距、摘要/誌謝/參考文獻 1.5 倍行距、正文 2 字首行縮排、圖說在圖下與表說在表上。
- 仍不符合或僅部分符合的主因，已不再是舊版那種全面性頁面設定錯誤，而是集中在三類：
- 前置頁還沒有套官方附件版型。
- 頁碼 section 邏輯尚未真正落成「前置羅馬、正文阿拉伯、書名頁/審定書不印頁碼」。
- caption / 章節深層層次仍有少量 parser 與正規化邊角案例。
