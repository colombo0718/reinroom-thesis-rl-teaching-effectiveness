# 口試簡報技術流程

> 給黃老師參考：本次口試簡報的製作方式。
> 整套工具鏈與工作流程公開於 [口試簡報/](.)。

---

## 核心工具：Slidev

- 開源簡報工具，由 **Vue.js 作者尤雨溪團隊**維護
- 官網：<https://sli.dev>
- 定位：給開發者用的 keynote
- 寫法：**Markdown**
- 渲染：瀏覽器（Vite + Vue）

---

## 工作流程（從零到 PDF）

```
1. 寫內容     → slides.md（Markdown，--- 分隔每一頁）
2. dev 預覽   → npm run dev → 瀏覽器 http://localhost:3030 即時預覽
3. 改完存檔   → 瀏覽器自動 hot-reload（不用手動 F5）
4. 匯出 PDF   → npm run export:pdf
              → playwright-chromium headless 抓 40 頁印成 PDF
```

---

## 關鍵設計

| 元素 | 做法 |
|------|------|
| **頁面切換** | Markdown `---` 三槓 |
| **版面樣板** | Frontmatter `layout: default / section / center` |
| **圖** | 論文 `images/` 用 `prepare.mjs` 同步到 `public/images/`，dev / build / export 前自動跑 |
| **排版** | UnoCSS（Tailwind 風格）class 直接寫，例如 `grid grid-cols-3 gap-4` |
| **方程式** | 內建 KaTeX 渲染（LaTeX 原樣寫）|
| **流程圖** | 內建 Mermaid |
| **講者註解** | `<!-- ... -->` 每頁尾巴，presenter mode 看得到 |
| **客製樣式** | 根目錄 `style.css` 自動載入 |
| **主題** | `theme: seriph`（內建學術風）|

## 與 PowerPoint 的差別

|  | Slidev | PowerPoint |
|---|--------|-----------|
| 寫法 | Markdown（純文字） | 點選拖拉 |
| 版本控管 | git diff 可讀 | 二進位檔，diff 無意義 |
| 數學 / 程式碼 | 原生漂亮 | 慘 |
| 細部排版 | CSS 全控 | 拖拉常對不齊 |
| 學習成本 | 要會 markdown + 少量 CSS | 點按式全民會 |
| 動畫 | 基本動畫 OK | 強 |
| 演示模式 | 有，內建 presenter view | 有 |

---

## 對整體工作流的好處

- **論文 md 跟簡報 md 同套寫法**，同個 git repo、同樣的 VSCode 編輯流程
- 圖只在論文 `images/` 維護一份，簡報自動同步，不會走鐘
- 修改紀錄都進 git，回溯方便
- 老師審查時看 GitHub 線上 PDF 或拉 repo 跑 dev 都行

## 如果想試試看

只需要一台機器裝好 [Node.js](https://nodejs.org/)：

```bash
npm create slidev@latest    # 建立新專案
npm run dev                 # 開始寫
npm run export              # 出 PDF
```

10 分鐘就能跑起第一份 demo 簡報。

## 技術選型的判斷邏輯

選 Slidev 而非 PowerPoint 的理由（按重要性排序）：

1. **整套工作流統一** — 論文用 markdown + git + VSCode，簡報用同套，學習成本邊際為零
2. **圖源單一** — 論文 21 張圖直接重用，不需要重做或重 export
3. **數學原生** — LaTeX 直接寫，跟論文一樣的方式
4. **版本控管** — 改了哪一頁 git diff 一目瞭然
5. **可程式化** — 排版用 CSS，可重複利用
6. **跨平台** — 任何瀏覽器都能放，PDF 也行

劣勢（誠實面對）：
- 學習門檻：要會 markdown 跟基本 CSS
- 複雜動畫：不如 PPT 強，但口試簡報用不到
- 互動性低：但 PDF 反而最穩，口試教室電腦不會出包
